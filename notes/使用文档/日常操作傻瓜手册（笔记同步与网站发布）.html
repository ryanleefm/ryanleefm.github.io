“同步笔记”和“发布网站”是两件独立的事。Git 插件同步成功后，网站还需要发布；发布网站也不会替你将笔记原文件提交到同步仓库。

1. 平时写笔记：照常使用 Obsidian

开始写之前

  1. 打开 Obsidian，确认打开的是 Obsidian-Sync-Git 这个库。
  2. 如果刚在另一台电脑写过笔记，等启动时的 Git 拉取完成。
  3. 想手动拉取：按 Ctrl+P，搜索并执行 Git: Pull。
  4. 若提示冲突或同步失败，先保留报错，别让两台电脑继续修改同一篇笔记。

新建、修改、删除、移动

操作怎么做下次发布后的效果
新建文字笔记在 Obsidian 中新建笔记，正常写作网站新增文章
新建 Canvas在目标文件夹的菜单中选择“新建白板 / New canvas”网站新增画布
修改内容直接编辑原笔记或 Canvas网站替换成最新内容
删除笔记在 Obsidian 文件列表中删除网站移除对应页面
重命名、移动尽量在 Obsidian 文件列表中操作，并留意更新内部链接的提示网站名称、目录和页面地址可能变化
加图片、PDF把附件放进这个库，再在笔记中引用支持的附件会一起发布

不需要自己编辑网页，也不需要启动 Quartz 或 Semantic Map Canvas 才能发布。Semantic Map Canvas 可以继续用于你本地的编辑体验，网站展示不依赖运行这个插件。

附件应保存在 vault 内。仅指向电脑上其他目录的文件链接，公众无法读取。删除笔记后，独立留在库内的图片、PDF 不会随之删除；确定没有其他笔记引用，再删除不用的附件。

换电脑或关机之前

  1. 在 Obsidian 中按 Ctrl+P。
  2. 搜索并执行 Git: Commit-and-sync。
  3. 等待完成，确认没有错误通知，再关闭或切换电脑。
  4. 到另一台电脑后，先拉取再编辑。

本机当前设有约每 10 分钟自动提交同步、打开库时拉取；需要 Obsidian 打开、电脑联网。切换电脑前主动同步一次，避免刚写完就关机。

2. 发布学习笔记：日常只需双击一次

  1. 确认本机 Obsidian 中已经有你想发布的最新内容。
  2. 打开资源管理器，进入 D:\020_Projects\Hexo-blog。
  3. 双击 发布学习笔记.cmd，保持弹出的窗口打开。
  4. 等它提示“上传成功”。如果显示“发布失败”，保留窗口中的报错。
  5. GitHub Pages 随后还需要完成构建。稍后打开 学习笔记网站，查看这次修改。
  6. 已提示完成的命令窗口可以按任意键关闭。

可以积累很多次编辑，最后统一发布一次。不必每写一句就发布，也不要同时打开多个发布窗口。

目前是本机一键发布，尚未设置“笔记推送 GitHub 后自动更新网站”。每次会扫描并重新生成笔记站，而非只上传这一篇。等待期间不需要重新配置工具。

新建和删除需要额外登记吗？

不用。现在使用全库模式，下次发布会重新扫描普通笔记和支持的附件。

  • 新增 .md、.canvas、.base 会自动纳入。
  • 删除原文件后，下次成功发布会移除对应的当前网页。
  • 删除或改名之后，别处引用它的链接也要检查；旧的收藏地址可能失效。
  • .obsidian、.git、.trash 等隐藏目录不会发布。
  • 当前全库公开，包含“使用文档”和未命名笔记。本手册也会在下次发布时公开。 私有 GitHub 同步仓库与公开网站的可见范围不同；普通笔记不会因为仓库私有而自动保密。
  • 想保留某篇笔记却不公开，请先让 AI 调整发布范围并验证，再发布；不要以为随手加一个 private: true 就已生效。

这里的删除是从网站当前版本移除；Git 仓库历史不会因此自动抹除。误删或需要恢复时，先暂停相关设备同步，让 AI 帮你从回收站、备份或 Git 历史中找回。

网站看起来没变化怎么办？

按顺序看：

  1. 命令窗口是否真的提示“上传成功”？
  2. 本机 vault 中是否有最新修改？另一台电脑的笔记可能还没同步过来。
  3. GitHub Pages 是否仍在构建？可看 网站发布记录。
  4. 在网页按 Ctrl+F5 强制刷新，再检查。
  5. 仍不对，把下面第 6 节的小纸条和报错一起发给 AI。

“上传成功”表示文件已推送 GitHub；“Pages 构建成功”和“网页显示正确”还需要分别确认。

3. 想先看看效果，不立即公开

这是可选操作；平时直接用双击发布即可。

打开 PowerShell，先输入：

Set-Location D:\020_Projects\Hexo-blog
npm.cmd run notes:build

等上一条成功，再输入：

npm.cmd run build -- --bail

成功后输入：

npm.cmd run notes:preview

浏览器打开 http://127.0.0.1:4002/notes/ 。这个命令窗口保持运行；看完回到窗口按 Ctrl+C 停止。这些命令不会发布网站。预览期间再改笔记，需要重新生成才能看到变化。

4. 原来的 Hexo 博客怎么用？

学习笔记与原博客文章仍是两个入口。

新建博客文章

在 PowerShell 中输入：

Set-Location D:\020_Projects\Hexo-blog
.\node_modules\.bin\hexo.cmd new "文章标题"

打开新生成的 D:\020_Projects\Hexo-blog\source\_posts\文章标题.md 写正文。修改旧文章直接编辑对应文件；删除文章也在这里操作，留意是否还有同名附件目录被其他内容引用。

发布

最省事：仍然双击 发布学习笔记.cmd，它会同时生成并发布笔记区域和整个 Hexo 博客。

如果这次只改了博客，不需要重新读取 Obsidian 笔记，可以分开运行：

Set-Location D:\020_Projects\Hexo-blog
npm.cmd run build -- --bail

确认生成成功后，再运行：

npm.cmd run deploy

普通 hexo generate / hexo deploy 使用已经生成好的学习笔记网页，不会重新读取 vault。--bail 放在生成阶段，用来让构建遇到错误时停止；deploy 后面不用加它，也没有 --dail 这个参数。

hexo clean 用来删除生成目录 public 和缓存 db.json，不会删除 source/_posts 或 Obsidian 原笔记。日常不必每次清理；显示异常时再让 AI 判断是否需要清缓存。

5. 报错时先保留哪些东西？

看到的内容先怎么做
punycode 的 DeprecationWarning此前构建出现过此提示，仍能成功；继续看末尾结果
LF will be replaced by CRLF这是换行符提示；继续看是否发布成功
Permission denied (publickey)SSH 认证失败，保留完整报错，让 AI 检查现有密钥与 GitHub 账号
fatal、FATAL、Error、发布失败复制从关键错误开始到末尾的文字，不要只截最下面一行
conflict、unmerged、UU暂停相关设备同步，先保留双方修改，再请 AI 处理
网页中图片、公式或 Canvas 不对提供具体笔记名、网页地址、原 Obsidian 与网页的对比截图

同时告诉 AI：你刚刚点了什么或执行了什么、希望出现什么、实际出现什么。不要在排错时反复重装依赖或删除目录。SSH 私钥、密码和令牌不要粘贴给 AI。
