新电脑接入指南（Windows与Linux）

新电脑接入指南：Windows 与 Linux

编写日期：2026-10-02，Asia/Shanghai。用于把已有的 GitHub 私有仓库接入另一台电脑，或在重装系统后恢复使用。

仓库：ryanleefm/Obsidian-Sync-Git，分支 main。正常接入不需要 agent；认证、Flatpak 权限或冲突难以判断时，可以把 Agent 交接说明 交给维护者。

先判断属于哪一种情况

情况应做什么
只重装 Obsidian，原同步库仍在备份后打开原目录，检查本机 Git、认证、插件和自动设置
全新电脑或库目录已经丢失按本指南克隆到新的空目录，再配置本机
准备用已有本地笔记加入同步先备份、暂停自动同步，按详细手册导入；不要直接覆盖或合并目录
原电脑还有未提交或未推送内容先保留并备份原电脑的数据；新电脑克隆只能取得 GitHub 上的内容

不需要再创建仓库，也不需要在新库运行 git init。原设备保留到新设备完成验证。不要把整份旧 .git、认证目录或 Linux .obsidian 直接复制到另一台电脑。

以下路径是示例。Windows 没有 D 盘时可以使用 C:\Users\你的用户名\Documents\Obsidian-Sync-Git，并统一替换后续命令的路径。Linux 使用当前用户的主目录，不固定为 rlee。

在同一终端依次操作，每阶段检查成功后再继续。遇到错误不要继续粘贴剩余命令。

一、新 Windows 电脑

W1. 安装和检查软件

安装 Obsidian 和 Git for Windows。Git 安装过程中保留第三方程序使用 Git 的 PATH 选项，以及 Git Credential Manager。仅安装 GitHub Desktop 不足以让 Obsidian Git 插件使用 Git。插件官方安装说明

安装完成后重新打开 PowerShell，执行：

git --version
where.exe git
git credential-manager --version

都应正常输出版本或路径。若刚安装 Git，完整退出所有 Obsidian 窗口后重开，让应用获得新的 PATH。

W2. 克隆现有私有仓库

本例使用 D:\Obsidian-Sync-Git。目标目录必须不存在：

if (Test-Path -LiteralPath 'D:\Obsidian-Sync-Git') {
    Write-Host '目录已存在，请停止并检查；不要覆盖。'
} else {
    git -c credential.helper= -c credential.helper=manager clone https://github.com/ryanleefm/Obsidian-Sync-Git.git D:\Obsidian-Sync-Git
}

这里临时指定 GCM 处理这次克隆。跟随浏览器提示登录 ryanleefm；若账户开启 2FA，按网页要求验证。无需复制原电脑的令牌，也不要把令牌写进 URL。

成功后检查：

git -C D:\Obsidian-Sync-Git status --short --branch
git -C D:\Obsidian-Sync-Git remote get-url origin

预期是 main…origin/main、无文件变更，origin 为本指南开头的仓库地址。若前一步提示目录已存在，先判断是否本来就是这个库；不能把该提示当作克隆成功。

W3. 备份新库

在首次修改本机设置之前，把新克隆完整备份到库外。已有其他笔记库时，也要另行备份那些原数据。

& {
    $ErrorActionPreference = 'Stop'
    $newDeviceBackup = 'D:\Obsidian-Sync-Backups\new-windows-' + [guid]::NewGuid().ToString('N')
    New-Item -ItemType Directory -Path $newDeviceBackup | Out-Null
    Copy-Item -LiteralPath 'D:\Obsidian-Sync-Git' -Destination $newDeviceBackup -Recurse -Force
    git -C "$newDeviceBackup\Obsidian-Sync-Git" fsck --full
    if ($LASTEXITCODE -ne 0) { throw '备份 Git 检查失败' }
    Write-Host "备份目录：$newDeviceBackup"
}

此检查核验 Git 对象。对于包含未提交笔记或附件的库，还要检查文件数量和内容或做哈希比对。

W4. 设置本库的 Git

git -C D:\Obsidian-Sync-Git config --local user.name ryanleefm
git -C D:\Obsidian-Sync-Git config --local user.email ryanleefm@gmail.com
git -C D:\Obsidian-Sync-Git config --local core.autocrlf false
git -C D:\Obsidian-Sync-Git config --local core.safecrlf warn
git -C D:\Obsidian-Sync-Git config --local pull.ff only
git -C D:\Obsidian-Sync-Git config --local push.default simple
git -C D:\Obsidian-Sync-Git config --local fetch.prune true
git -C D:\Obsidian-Sync-Git config --local --replace-all credential.https://github.com.helper manager

认证 helper 限定在此库的 GitHub 地址，使用本机 GCM。提交署名是 Git 记录，不等于登录认证。以上命令不修改全局配置。

W5. 打开库并安装插件

  1. Obsidian → 管理仓库 → 打开本地仓库，选择 D:\Obsidian-Sync-Git。
  2. 设置 → 第三方插件 → 浏览，搜索 Git，安装并启用。
  3. 按插件页面检查要求的最低 Obsidian 版本；本次原设备使用 Obsidian 1.13.7，插件为 2.41.0/2.41.1，这些是历史记录，不要求新设备强行降级。
  4. 三个自动间隔先设为 0，Pull on startup 先关闭。
  5. 开启 Pull on commit-and-sync 和 Push on commit-and-sync。
  6. 合并方式采用 Merge；有冲突时保留人工处理，不自动选择某一端的内容。

没有 data.json 时可能只是尚未保存过设置。备份整个 .obsidian 目录，不必手工创建空 JSON。

接着执行本指南“三、所有新设备都要做的验证”。

二、新 Linux 电脑

L1. 选择一条安装路径

路径适用情况Git 与认证运行位置
A：普通 Linux 安装使用系统可访问的 Obsidian，例如 AppImage宿主 Git 与宿主 gh
B：Obsidian Flatpak与当前 Zirconium 类似的安装方式先验证应用内 Git、gh，优先用应用内工具

只执行其中一条，随后到 L2 继续。bootc 等不可变系统不要直接套用普通系统的包安装命令。本次 Zirconium 的 Flatpak 路径已验证；新机器的运行时内容和权限仍需重新检查。

插件官方列出了 AppImage 的支持情况及 Flatpak 的访问限制。安装兼容说明

路径 A：普通 Linux

  1. 安装 Obsidian。
  2. 按发行版安装 Git，再按 GitHub CLI Linux 安装说明 安装 gh。
  3. 检查版本并登录：
git --version
gh --version
gh auth login --hostname github.com --git-protocol https --web
gh auth status --hostname github.com

Git 的发行版安装方式见 Git 官方 Linux 安装页。例如普通 Debian/Ubuntu 可用 sudo apt-get install git，普通 Fedora 可用 sudo dnf install git；gh 的软件源与包名称按其官方页面选择。

登录 ryanleefm。若询问是否同时配置 Git 认证，选 No：本指南稍后只配置这个仓库的 helper。完成网页授权后回到终端，确认登录流程真正完成。若 gh 提示退回明文凭据存储，先处理本机密钥环；认证文件始终放在笔记库外。

在当前终端定义：

vaultGit() { git "$@"; }
obsidianCredentialHelper='!gh auth git-credential'

然后跳到 L2。

路径 B：Flatpak，包括类似 Zirconium 的电脑

按系统软件商店安装 Flathub 的 Obsidian，应用 ID 为 md.obsidian.Obsidian。若已经配置好 Flathub，也可执行：

flatpak install flathub md.obsidian.Obsidian

Flatpak 或 Flathub 未配置时先完成发行版的安装步骤。Flatpak 使用说明

检查应用内工具与权限：

flatpak info md.obsidian.Obsidian
flatpak info --show-permissions md.obsidian.Obsidian
flatpak run --command=git md.obsidian.Obsidian --version
flatpak run --command=gh md.obsidian.Obsidian --version

Git 或 gh 不存在时先停止。当前 Zirconium 的应用包含这些工具，但不能假定将来的所有 Flatpak 版本都一样；不要在没有验证工具和认证路线时继续。

登录：

flatpak run --command=gh md.obsidian.Obsidian auth login --hostname github.com --git-protocol https --web
flatpak run --command=gh md.obsidian.Obsidian auth status --hostname github.com

仍使用 ryanleefm，认证协议为 HTTPS。如提示是否配置 Git 认证，选 No，之后使用仓库本地 helper。若 gh 提示无法使用系统密钥环并退回明文存储，先处理本机凭据存储，不把认证文件放入笔记库。gh 登录和存储说明

在当前终端定义：

vaultGit() { flatpak run --command=git md.obsidian.Obsidian "$@"; }
obsidianCredentialHelper='!f() { if [ -f /.flatpak-info ]; then gh auth git-credential "$@"; else flatpak run --command=gh md.obsidian.Obsidian auth git-credential "$@"; fi; }; f'

此 helper 在 Flatpak 内调用应用 gh，在宿主调用时转入这个 Obsidian Flatpak。它没有密码或令牌。/.flatpak-info 是运行中的 Flatpak 沙箱元数据文件。Flatpak 元数据说明

当前原 Zirconium 机器已有正常工作的 helper，无需因为本指南而改写。新指南使用沙箱标识区分调用位置，避免新宿主恰好装了另一份 gh 时取错登录凭据。

L2. 克隆到当前用户的新目录

前面选定的 vaultGit 函数和 obsidianCredentialHelper 变量只存在于当前终端；关闭终端后要重新定义相应路径的函数，或使用对应的完整 Git 命令。

vaultParent="$HOME/Documents"
vaultPath="$vaultParent/Obsidian-Sync-Git"

如果 Documents 在本机有不同路径，在这里替换 vaultParent，后续命令继续使用变量。先确认目的目录不存在：

if [ -e "$vaultPath" ] || [ -L "$vaultPath" ]; then
    echo '目录已存在，请停止并检查，不要覆盖。'
else
    mkdir -p "$vaultParent" &&
    vaultGit -c credential.https://github.com.helper= \
        -c "credential.https://github.com.helper=$obsidianCredentialHelper" \
        clone https://github.com/ryanleefm/Obsidian-Sync-Git.git "$vaultPath"
fi

成功后检查：

vaultGit -C "$vaultPath" status --short --branch
vaultGit -C "$vaultPath" remote get-url origin

预期 main…origin/main 且没有变更。克隆失败时不继续 L3。

Flatpak 报目录访问错误时先检查已有权限。如果确实缺少所选目录的访问权限，可以只授权这个目录，再重启应用：

flatpak override --user --filesystem="$vaultParent" md.obsidian.Obsidian

这一行只适用于路径 B，并且仅在确认需要时执行。不要通过授予整个主机访问或重置全部权限来猜测修复。Flatpak 文件访问说明

L3. 备份新库

在配置本地 Git 和安装插件前，关闭新库的 Obsidian 窗口，备份整个新克隆：

(
    set -eu
    mkdir -p "$vaultParent/Obsidian-Sync-Backups"
    newDeviceBackup="$(mktemp -d "$vaultParent/Obsidian-Sync-Backups/new-linux-XXXXXXXX")"
    tar -czf "$newDeviceBackup/vault.tar.gz" -C "$vaultParent" Obsidian-Sync-Git
    tar -tzf "$newDeviceBackup/vault.tar.gz"
    printf '备份目录：%s\n' "$newDeviceBackup"
)

最后列出压缩包只验证可读性；已有未提交笔记时再做文件数量和哈希核验。已有其他原始库的备份要另外完成。

L4. 配置此库

在同一个终端执行：

vaultGit -C "$vaultPath" config --local user.name ryanleefm
vaultGit -C "$vaultPath" config --local user.email ryanleefm@gmail.com
vaultGit -C "$vaultPath" config --local core.autocrlf false
vaultGit -C "$vaultPath" config --local core.safecrlf warn
vaultGit -C "$vaultPath" config --local pull.ff only
vaultGit -C "$vaultPath" config --local push.default simple
vaultGit -C "$vaultPath" config --local fetch.prune true
vaultGit -C "$vaultPath" config --local --replace-all credential.https://github.com.helper ''
vaultGit -C "$vaultPath" config --local --add credential.https://github.com.helper "$obsidianCredentialHelper"

helper 是调用程序的逻辑，凭据由 gh 管理。不要改成 credential.helper=store，不要把密码写进 Git 配置。

L5. 用 Obsidian 打开并配置插件

  1. 在文件管理器确认新库路径。
  2. Obsidian → 打开本地仓库，选择该目录。
  3. 安装并启用第三方插件 Git，确认 Obsidian 版本满足插件要求。
  4. 自动间隔全部保持 0，启动拉取保持关闭。
  5. 提交同步时拉取、推送开启；采用 Merge，冲突时人工处理。
  6. 确认中文和附件显示正常，再进入第三部分。

Flatpak 字体问题可先检查：

fc-match ':lang=zh-cn'
flatpak run --command=fc-match md.obsidian.Obsidian 'Noto Sans CJK SC:lang=zh-cn'

不要仅凭宿主匹配正常就认定应用能使用中文字体。当前 Zirconium 的修复使用了应用专用 fonts/obsidian-cjk 目录和 Noto CJK 字体；新电脑只有出现同样问题时才需要参考 故障排查表 重做检查，不要照搬旧用户名路径。

三、所有新设备都要做的验证

登录 GitHub 后确认仓库页面标为 Private，再进行推送测试。如果可见性异常，先停止上传并核对仓库设置。

1. 验证拉取

在新设备 Ctrl+P → Git: Pull，确认没有认证错误。打开已知笔记，检查正文、中文和附件。

2. 验证新设备推送

在新设备创建一篇唯一命名的测试笔记，例如 接入测试-设备名称.md，正文写明来源。只放测试内容，不复制私人原库进行测试。

Ctrl+P → Git: Commit-and-sync，等待完成；在旧设备执行 Git: Pull，确认出现该笔记且内容一致。

3. 验证反向接收

在旧设备创建另一篇测试笔记并同步。新设备执行 Git: Pull，确认收到。两端顺序执行，不同时编辑同一篇笔记。

查看状态：Windows 用 git -C 新库路径 status —short —branch；Linux 在前述终端用 vaultGit -C “$vaultPath” status —short —branch。双方工作区应干净，已推送、拉取后能对上预期提交。

手动双向同步通过后，在库外备份新生成的 .obsidian。它包含新设备的插件和设置，不会进入 Git。

4. 开启并验证自动同步

设置 → Git：

选项值
Auto commit-and-sync interval (minutes)10
Use separate commit and push intervals关闭
Auto push / Auto pull interval (minutes)0
Pull on startup开启
Pull on commit-and-sync开启
Push on commit-and-sync开启

再创建一篇新的自动测试笔记，保持库打开、联网、电脑不休眠，等待约 10～12 分钟。期间不手动提交或推送。检查文件的提交记录，并在另一端拉取确认。

这一步区分“配置已开启”和“定时任务已实际运行”。以后切换设备前仍建议手动 Commit-and-sync，另一端编辑前先 Pull。

5. 完成接入后

  • 正常使用新同步库；保留旧设备与外部备份。
  • 插件、自动设置、界面、字体需要逐设备配置，因为 .obsidian 被忽略。
  • 密码、令牌、2FA 恢复码不能写进同步笔记。.gitignore 不能识别正文里的秘密。
  • 导入旧笔记是单独阶段，先备份并暂停自动任务，按 详细用户手册 操作。
  • 认证或冲突报错时查看 故障排查表；需要 agent 时提供 交接说明，以及经过脱敏的错误和状态输出。
