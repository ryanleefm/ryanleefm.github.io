Obsidian Git 同步故障排查表

记录日期：2026-10-02。路径、当前设置和备份方法见 详细手册。维护者先读 Agent 交接说明。

遇到错误先保留原文件。冲突、丢失、覆盖风险出现时，暂停自动同步并在库外备份。下面的检查尽量从只读命令开始，涉及拉取、修改配置或恢复文件时先确认备份。

1. 按症状排查

现象或错误常见原因先检查什么处理方法
超过 10 分钟仍未同步库未打开、应用休眠、定时任务暂停、设置错误或网络错误正确库是否打开；三个间隔；插件通知；新文件的提交记录确认提交同步间隔为 10，分开间隔关闭，提交时推送开启；保持应用和网络可用。自动测试期间不要手动推送掩盖问题
Obsidian 找不到 GitGit 未加入应用 PATH，或安装后应用仍保留旧环境Windows where.exe git；Linux Flatpak 内 git —versionWindows 完整退出后重开 Obsidian；必要时在插件中指定实际 git.exe。Linux 检查应用内 Git，不只检查宿主
Repository not found仓库地址错误、登录账号错误、私有库权限不足origin 地址；当前认证账号；GitHub 网页是否可访问该私有仓库用 ryanleefm 重新授权正确账户；保留 HTTPS 地址，不在 URL 嵌入令牌
Authentication failed / 401OAuth 或 GCM 凭据失效Linux gh auth status；Windows credential.helper；网页授权是否完成按浏览器流程重新登录。不要粘贴令牌到聊天或写入笔记
403 / permission denied无写权限、授权不足或仓库策略阻止登录账户、仓库权限、完整错误文本修复权限后重试；不要改成公开仓库绕过权限问题
ahead N有本地提交未推送git log；网络和认证错误保留提交，解决网络或认证后执行 Commit-and-sync；推送拒绝时先看分叉情况
behind N已知远端领先当前库、工作区是否有修改备份后使用插件 Pull；工作区有修改时先判断是否与远端冲突
non-fast-forward / 分叉两端都产生提交fetch 后的 ahead/behind、日志图、冲突文件暂停自动同步、备份，检查双方内容后合并。不要默认改用 rebase 或强推
UU / unmerged / 冲突标记同一文件同一区域两端都被修改git status；冲突文件两边内容备份两份版本，人工合并并提交，确认后推送。插件 Merge 策略应保留人工选择
index.lock 已存在Git 操作仍在进行，或上次异常退出Git/Obsidian 进程与当前任务先等待或正常退出；确认无进程占用并备份后再决定是否处理锁文件，不自动删锁
文件没进入 Git命中忽略规则，或编辑的不是同步库git status；git check-ignore -v — 路径对照实际路径和 .gitignore；不要为了同步配置而取消整个 .obsidian 忽略
布局、插件、字体没同步.obsidian 被设计为本机保存是否只是设备设置不同两端独立安装和设置；笔记内容正常即可
data.json 不存在插件尚未保存过设置，也可能打开了错误的库.obsidian/plugins/obsidian-git/manifest.json 是否存在先备份整个 .obsidian。检查实际库路径；不需要手工创建空 data.json
New-Item 提示目录已存在重复使用同一个备份目录变量已有目录是否为先前备份保留已有备份，改用新目录；仅建目录不代表复制成功
Copy-Item 被 Ctrl+C 中断复制未执行完或输入被取消备份文件、Git 对象是否完整在源库静止时重新完成复制，再检查。不要删除源库
中文方框、空白或缺字Flatpak 字体不可见，或旧进程未重启宿主与 Flatpak 内 fc-match 的差异；是否所有窗口都退出用本次字体方案检查；完整重启应用。仅重开一个库窗口可能仍使用旧主进程
LF/CRLF 提示两端换行策略不同.gitattributes、core.autocrlf、本次 diff本项目 Markdown/Canvas 使用 LF，core.autocrlf=false；先看实际差异，避免批量改写全部笔记
单个大附件推送被拒绝超过普通 Git 文件限制附件大小和错误文字暂停提交，评估 LFS 或外部附件存储；新增删除提交通常不能移除此前提交里的大文件
登录地点与所在地不同上游出口、地理定位偏差或异常登录是否刚由本人发起授权；时间、设备和账户不确定时停止授权并核对账户。学校网络出口只是可能原因，不作为安全保证
开启 2FA 后需重新登录新会话验证、凭据撤销或授权过期网页和认证工具具体提示按浏览器要求完成 2FA；保留仓库，通常无需重建 Git 配置
笔记被误删或误改编辑操作、同步删除、冲突处理失误本地回收站、库外备份、文件 Git 历史暂停两端同步，恢复到新的目录或副本，比较后再提交恢复内容
新配置电脑仍不能同步只复制了笔记，未配置本机 Git/认证/插件本机环境、凭据、插件启用状态按详细手册完成本机配置，再手动同步验证

GitHub 普通 Git 会阻止大于 100 MiB 的文件；本项目没有配置 LFS。官方大小限制

2. Windows 检查命令

以下命令不会修改笔记：

git --version
where.exe git
git credential-manager --version
git -C D:\Obsidian-Sync-Git status --short --branch
git -C D:\Obsidian-Sync-Git log -5 --oneline
git -C D:\Obsidian-Sync-Git remote get-url origin
git -C D:\Obsidian-Sync-Git config --get credential.helper
Test-Path -LiteralPath 'D:\Obsidian-Sync-Git\.obsidian\plugins\obsidian-git\manifest.json'

预期远端：https://github.com/ryanleefm/Obsidian-Sync-Git.git。如果远端出现嵌入式用户名、密码或令牌，不要把原始输出发给别人。

GCM 已安装不等于 Git 必然正在使用它；检查 helper。插件官方建议 Windows 使用 Git Credential Manager。官方安装说明

3. Zirconium 检查命令

git --version
git -C /home/rlee/Documents/Obsidian-Sync-Git status --short --branch
git -C /home/rlee/Documents/Obsidian-Sync-Git log -5 --oneline
git -C /home/rlee/Documents/Obsidian-Sync-Git remote get-url origin
flatpak info md.obsidian.Obsidian
flatpak info --show-permissions md.obsidian.Obsidian
flatpak run --command=git md.obsidian.Obsidian --version
flatpak run --command=gh md.obsidian.Obsidian auth status --hostname github.com

gh auth status 的输出可能带掩码凭据信息，分享前检查；禁止增加显示真实令牌的选项。不要运行 gh auth token 或输出 git credential fill 的密码字段。

核对私有状态：

flatpak run --command=gh md.obsidian.Obsidian repo view ryanleefm/Obsidian-Sync-Git --json nameWithOwner,isPrivate,visibility

必须是 isPrivate=true 且 visibility=PRIVATE；异常时停止笔记上传。

4. 中文字体专项检查

fc-match ':lang=zh-cn'
flatpak run --command=fc-match md.obsidian.Obsidian 'Noto Sans CJK SC:lang=zh-cn'
flatpak run --command=fc-list md.obsidian.Obsidian ':lang=zh'

宿主能匹配中文，不代表 Flatpak 能匹配。当前应用专用字体目录：

/home/rlee/.var/app/md.obsidian.Obsidian/data/fonts/obsidian-cjk

应包含 NotoSansCJK-VF.ttc 和 NotoSansMonoCJK-VF.ttc。界面/正文设为 Noto Sans CJK SC，代码字体设为 Noto Sans Mono CJK SC。

先正常退出所有 Obsidian 窗口，再重开。如果主进程仍在运行，先确认窗口和正在执行的同步任务；后续 agent 不应直接强杀应用。字体问题不应通过重新编码或覆盖笔记内容来处理。

5. 冲突处理流程

  1. 暂停两端自动任务，备份两个库，保留未提交修改。
  2. 确认 Git 是否正在 merge 或 rebase，列出冲突文件。
  3. 将双方版本另存到库外，比较内容。
  4. 人工决定保留、组合或建立两份笔记。
  5. 检查正文中没有遗留 <<<<<<<、=======、>>>>>>> 冲突标记。
  6. 只暂存确认后的文件，完成相应合并操作并推送。
  7. 另一端拉取检查，确认内容和附件后恢复定时同步。

不要拿 reset —hard、clean -fd、push —force 或删除 .git 作为默认修复步骤。

6. 提供给维护者的信息

提供：系统、Obsidian/插件/Git 版本，库路径，错误原文，git status 输出，最近几个提交，是否已备份，是否两端同时编辑。

不提供：真实密码、访问令牌、2FA 秘钥或恢复码，未脱敏的认证配置、私密笔记正文。需要查看笔记时先由用户选择范围。
